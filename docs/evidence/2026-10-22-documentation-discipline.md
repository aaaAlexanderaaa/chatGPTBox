## Reader and preservation review

The same implementing context reviewed these routes; this is not an independent
consumer trial:

1. A new contributor can go from either README to Contributing and find the
   actual Node version, available scripts, artifact paths, and limits of tests.
2. Browser assistant work goes from AGENTS/map to the October product direction
   and current contracts. The earlier schema exploration and its fixtures remain
   accessible without becoming an implementation requirement.
3. A protocol task reaches the adaptation skill, current code and API owner;
   dated bundles/retry constants are clearly source evidence.
4. A provenance question can find old product text, decisions, roadmaps and
   test reports without having their branch/task instructions applied today.
5. A docs-only contributor has an executable local check and a matching PR job.

The preservation check compares the archived product bodies with their original
Git versions, allowing only the rebased relative links. Historical plans,
decision records, designs and reports retain their original body beneath the new
metadata/status notice. Still-live boundaries are routed to current owners;
unproved acceptance remains visible rather than being declared successful.

## Limits

No product runtime, provider request, stored data, or external account was changed
by this repair. Existing source/configuration checks are not a claim of live
provider acceptance or full extension release validation. The new CI job has not
run on GitHub in this session. Subsequent agent retrieval/use and improvement in
real project quality require later observation; retaining a rule alone does not
prove it changed behavior. The checker validates supported structural syntax,
not the truth of prose, remote links, HTML image/link attributes, or every form
of CommonMark. Original private conversations and captures remain unavailable.
