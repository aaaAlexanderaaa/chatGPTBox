## 已决

### D-1 · 产品身份：一个产品叙事，平台 + 模块装配
- 背景：融合 agent 引擎后，是一个产品还是两个产品？
- 决策：对外叙事一个产品（"任何引擎，任何页面，按你的方式"），对内装配
  平台 + 可选模块。dsh 驾驶舱是"L3 引擎点亮的表面"，不是第二产品。
- 理由：从"帮我总结这段"到"让 agent 去改这个仓库"是同一意图的两种力度；
  拼接式叙事会让 14 个引擎变成 14 个功能。

### D-2 · dsh 定位：第一个 L3 引擎模块
- 决策：DeepSeek Harness 以引擎模块接入，默认关闭；对不用 agent 的用户，
  它只是引擎列表里一张卡片，不占注意力。
- 理由：大部分用户大部分时间在调 API；agent 是谱系顶端不是主角。

### D-3 · ChatGPT Web：功能冻结，整体搬迁
- 决策：功能与协议一行不动；其端点配置、历史同步、备份、调试视图收拾到
  一个屋顶下，独立成模块。设置 IA 中从"散落多处的 section"变成一个有门牌的地方。
- 理由：已构建好的稳定功能，只解决"住在哪"，不解决"怎么活"。

### D-4 · 会话列表：维持本地记忆 + 引擎绑定
- 决策：扩展的会话列表只收从扩展诞生的会话（本地记录 + 按引擎附服务端
  绑定）；不导入引擎侧原生会话（chatgpt.com 上开的对话、dsh web 开的 session）。
  dsh 的会话列表住在驾驶舱里。
- 理由：混入外来会话立即引出"改名删除听谁的"的归属问题，价值很小。

### D-5 · L3 表面形态：浮窗长审批卡，驾驶舱住 sidepanel/全页
- 决策：浮窗对 L3 引擎长出审批卡与轻量过程；完整时间线与审批管理住
  sidepanel/全页驾驶舱。对 L1 保持纯净聊天窗。
- 理由：L3 不被"调用"而被"参与"；"绝不错过审批"必须成立在用户真正
  所在的表面（浮窗）上。

### D-6 · OS 通知进 Phase 1；默认只批不打扰
- 决策：审批/提问到达且无 UI 附着时发系统通知 + badge；turn 完成默认不通知。
- 理由：dsh 自带 web 客户端没有 OS 通知——这是扩展对存量方案最实的增量；
  安静原则：只有"需要你"的事件才说话。

### D-7 · 审批同等醒目，v1 不做风险分级
- 决策：所有审批卡同等视觉强度，不按工具名/参数做静态风险分级。
- 理由：先保证"每一扇门都同样醒目"；分级做早了容易给用户虚假安全感。

### D-8 · auto-approve 是每会话手边的显式开关
- 决策：自动审批从全局设置提为每 session 的显式开关，状态永远在视野内；
  默认关闭。
- 理由：这是风险决策，应该在手边而不是埋在 Advanced 里当暗门。

### D-9 · 驾驶舱先做全页档
- 决策：console 先做全页（宽度自由、最快验证台账布局），sidepanel 作为
  同一套组件的窄档随后，popup 为 peek 档。
- 理由：一套响应式组件三个宽度，先验证信息密度最高的形态。

### D-10 · 设置重构：先立骨架，渐进迁移，不大爆炸
- 决策：先做模块缝（注册机制 + 目标 IA 骨架，旧编辑器原样嵌入），dsh 作为
  第一个入住新结构的模块，存量域随后逐个"纯搬运"式迁移；ChatGPT Web
  搬迁为第一次迁移验证。
- 理由：缝存在之前搬 section 只是手工搬运；大爆炸是纯风险无收益动作，
  且与进行中的 PopupNew 迁移对撞。

### D-11 · 侧栏缺席合法（契约判例）
- 决策：搜索侧栏定级"环境级"——偶发不出现不算缺陷，出现即必须完整。
- 理由：环境级与应答级的分界判例，定它整个分级体系就活了。

### D-12 · 换引擎披露：切换瞬间一行提示
- 决策：切换时明示记忆语义（保留什么、丢失什么），一行提示，不拦截确认。
- 理由：披露即履约，不必打扰得恰到好处。

### D-13 · 明确不做清单
- 决策：不做多 harness 抽象（留 capability 缝）；扩展内不执行工具；
  不做 dsh 的 settings/credentials 管理（读展示可以，写不做）；
  不做跨引擎统一会话列表（见 D-4）；不迁移外来会话。
- 理由：见 definition.md"明确不承诺什么"。

### D-16 · 驾驶舱中栏是台账，不是气泡流
- 决策：叙述是主角（散文语域）、行动可检视（机器语域）、决策最响亮
  （决策语域）；气泡形态只存在于浮窗（L1/L2 表面自适应）。
- 理由：驾驶舱的问题空间是"监督一个替你干活的东西"，不是对话。

### D-17 · "等你"一色制，落双 token
- 决策：审批与提问同用琥珀色，但定义 `--dsh-waiting-approval` 与
  `--dsh-waiting-question` 两个 token，v1 同值，允许日后分色。
- 理由：一个概念（等你）不该两种颜色；但保留不改结构就能分色的余地。

### D-18 · v1 无第三栏
- 决策：host 状态收进全局头，jobs/queue 收进会话栏计数，不养右侧栏。
- 理由：克制；右栏是密度陷阱，等真实需求再立。

### D-19 · Popup 档保留 composer
- 背景：曾提议 popup 只解堵不输入；另查实当前 fork 的 popup 是纯设置面板，
  聊天在页面浮窗——"保留"实为给 popup 加回聊天能力。
- 决策：popup = 等待卡钉顶（解堵第一职责）+ 会话尾部 + composer；
  硬要求草稿自动保存，任何失焦不丢字。
- 理由：砍输入是用砍能力躲避局促与丢稿两个风险，正确解法是窄档组件 +
  草稿持久化；quick ask 在浮窗不可用的页面应落在 popup。

### D-14 · ApiModes 归站点（集成）
- 背景：按站点指定引擎（"GitHub 用 Claude"）是站点的属性还是引擎的属性？
- 决策：归**集成（站点规矩）**。用户提问路径是"我想改这个站点"，
  引擎只是站点属性里被选择的一项。
- 理由：站点适配的归属由适配方持有；引擎目录保持"描述引擎本身"的纯粹。

### D-15 · 首启：检测优先，但先取模型
- 决策：检测到已登录 ChatGPT 网页会话即可直接开聊，但**先获取该账号的
  模型列表再定默认**，不硬编码假设 5.6 thinking 可用（免费用户可能只有 Auto）。
- 事实核对（2026-08-15）：客户端已拉取账号真实可用模型并在所选不可用时
  自动回退（client.mjs 模型解析链），免费账号不会坏。
- 遗留（不阻塞本次重构，往后放）：设置侧模型选择器未按账号可用性过滤，
  会展示账号用不了的档位。

### D-20 · 执行顺序：缝与首个客户同步成型（修正 D-10 实施注记）
- 背景：D-10 原实施注记为"先做模块缝（R0）→ dsh 入住 → 存量迁移"。
  产品轮结束后重审：缝先行是凭空造抽象，且 ChatGPT Web 搬迁验证的是
  "搬迁"半边而非"新建"半边。
- 决策：Phase A = dsh 模块首建，最小缝从 dsh 真实需求中同步提取；
  Phase B = 表面扩展（sidepanel/popup/浮窗审批卡/A 路径派活）；
  Phase C = 存量收割（ChatGPT Web 冻结搬迁为第一刀，之后 Engines 抽取、
  ApiModes 归 Sites、Tools 独立）；Phase D = 首启体验（D-15 落地）。
  dsh 从第一天住模块结构，旧结构接触点只有 B 才接的 provider 注册，
  先后颠倒无返工。
- 理由：证明点（agent 驾驶舱、浏览器成为 agent 的眼睛）最快到达；
  存量清理是收割不是开荒。全文见 [roadmap.md](./roadmap.md)。
