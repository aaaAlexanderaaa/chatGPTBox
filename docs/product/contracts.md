# 产品行为与失败边界

本文拥有跨功能约定。[产品定义](definition.md)拥有总入口；
[浏览器助手方向](browser-assistant.md)拥有当前工作入口与复用方式的产品设计。
这里的约定用于判断改动是否符合已接受方向，不是所有承诺均已实现或验收的
声明。具体接口与使用步骤由对应文档维护。

## 所选能力与材料范围

- 用户选择的连接身份应可见；不能把 API、网页连接或 agent 的类别当作能力
  保证。是否读取链接、支持图像、调用工具或跨中断继续，要按实际能力说明。
- 仅发送链接、发送选文、读取正文、改写输入分别保留自己的范围。不能因连接
  读不了链接就偷偷上传正文，也不能暗示已看见未取得的内容。截取、缺失和
  不支持的状态要说明，并提供调整方式。
- 用户主动运行才发送本次材料；页面标注、输入替换、审批等实际效果有明确
  动作。输入替换必须防止覆盖调用后发生的编辑，并在可用范围内支持撤销。
- 页面功能的当前格式、连接优先级、预览与结果使用方式见
  [使用说明](../browser-assistant.md)。工程探索中的配方 schema、执行器和
  任务账本不属于当前格式或已确认架构。

## 应答、失败与恢复

用户主动召唤的浮窗和页面功能必须给出答案、进度或明确失败；等待不能以无
反馈的转圈代替状态。具体时限由对应操作的接口定义，不能编造一个全局数字。
错误要说明已知状态、是否可能已经产生效果，以及用户下一步能做什么。

搜索页集成可以因环境不适用而不出现，但出现时不能展示残缺成功态或破坏原
页面布局、抢走输入焦点。明确归属于扩展的内容应能与站点原有内容区分。

不把残缺流当完整答案，不把静默失败当成功，不暗示不存在的记忆。停止请求
应传到实际执行方；远端是否停止未知时如实说明。不能为了显示成功而伪造、
删除或改写底层记录。

## 引擎配置与会话归属

API 使用自定义提供商及其启用模型。厂商模板是预填配置，不是互不相通的
固定提供商系统。OpenAI 兼容连接以 `/v1` 为基础地址读取 `/models`，失败时
允许手填；特殊格式与实际字段由配置代码和设置界面维护。网页模型列表来自
账号的实际可用能力，不能用旧的硬编码目录宣称账号支持某模型。

2026-09-17 的已接受改写明确不兼容早期“每家固定 URL + model”的提供商配置；
不能从旧路线图的“升级零丢失”推导出这部分也有迁移保证。对话和设置仍可
导出，升级后的提供商需要按实际情况重新配置。来源保留在
[引擎改写记录](../plans/2026-09-17-engines-providers.md)。

扩展自己的会话列表与引擎侧历史各有归属。读取或缓存远端历史不等于将其
混进扩展自己创建的会话列表。DeepSeek Harness 全页客户端可以展示该实例
的工作区和会话。换连接时应说明哪些上下文会保留、哪些记忆不能继续；不能
仅换名称而暗示无缝继承。缓存与恢复的具体规则由
[缓存契约](../cache-lifecycle.md)和[网关恢复契约](../api-server.md#at-most-once-writes-and-bounded-recovery)维护。

同一提供商内部换模型保留远端绑定。跨提供商切换保留本地可见记录，开始新的
远端会话；切回也不复活旧绑定。选择前说明数据流向：API 将按既有上下文长度
重发本地记录，网页引擎和 DSH 新会话只收到本次问题。运行中不切换，先 Stop。
本地记录与远端绑定代次分别持久化，旧快照不能把已解除的绑定恢复回来。
另一个窗口已改变连接时，旧窗口不能覆盖新的存储绑定；保存冲突须显示，保留
当前视图和未发草稿，暂停输入并提供重新打开已保存对话的入口。
仍在运行的请求保留明确的停止入口；保存冲突不解除用户的停止能力。
已保存对话的请求在后台开始执行前校验存储中的绑定与存在性；不等待异步保存
报错后才阻止派发。未获开始确认时保留输入，明确的新请求才解除先前终态。
校验中的新请求保持等待状态；拒绝后展示本次失败原因并恢复操作，先前的停止
确认不能提前结束它。
重试失败、停止、断流或未获发送许可时，在持久记录中保留之前的完整回答；只有新回答成功后
才替换对应的本地记录。

清空对话保留当前列表项的身份和连接选择，清除正文并开始新的远端绑定；旧窗口
和旧快照不能恢复已清空的绑定。首个问题未显示为气泡的卡片也遵守同样的重试
记录规则。提供商拒绝请求时保留未发草稿，只有本次提供商已接受的证据才确认提交。

## 网页引擎与真实账号

ChatGPT Web 与 Grok Web 复用用户自己的站点登录会话，内容质量由服务方决定。
登录失效、配额、上游变更和访问受限必须如实呈现；不能把账号风险转化为
后台重复写入、换模型重发或不透明的自动探测。

已发出但结果不确定的写请求不能被当作未发生而自动重发。幂等标识不证明
远端恰好执行一次。读状态、读历史与发送新消息是不同操作；恢复只读取已知
会话/消息的状态。网关的鉴权、请求身份、确认与恢复边界由
[API 契约](../api-server.md)和[MCP 契约](../mcp-server.md)维护。
Grok 的账号、只读探测与失败边界保留在
[专项设计](2026-08-17-grok-web-design.md#账号安全优先对标-chatgpt-web)。

2026 年 8 月的 ChatGPT Web“冻结搬迁”只约束当时的结构搬迁，不禁止之后
已授权的官网协议适配。新的适配以实际请求和当前代码为证据，遵守项目的
[适配流程](../../.agents/skills/chatgpt-web-adapt/SKILL.md)。

## 外部 agent 与页面操作

DeepSeek Harness 的执行、权限、会话和工具由本机引擎拥有。扩展显示进度、
审批、提问和结果，并把用户动作传回引擎。浮窗/popup 的轻量交互与完整客户
端的页面范围不能混淆。端点、原生调用与完整客户端目标以
[专项设计](2026-08-18-dsh-full-client-design.md)为准。

未经用户显式开启相应会话的自动审批，不能替用户通过审批；开关状态应清楚
可见。需要用户时应可找到并应答，完成通知默认保持安静。审批可达性和完整
客户端对等仍需真实环境验收，不因旧阶段标有勾选就视为通过。

这不恢复已删除的扩展内 Assistant / ZIP Skills / HTTP MCP 运行时。
本地 MCP 服务对外暴露 `ask_chatgpt`，DeepSeek Harness 的 skills 属于外部
引擎，页面功能是可保存的浏览器做法，三者不是同一个系统。

## 数据与验证

凭据保存在用户本地，发送到所配置的服务端点；不能增加未经授权的第三方
转发。配置、功能导出和诊断数据的内容不同，不能宣称所有导出都不含敏感
信息。可选历史同步或恢复读取属于已配置的后台活动，隐私说明不能写成
“只有点击发送才会联网”。

验证应观察用户实际完成工作、材料范围与外部效果，而非仅检查按钮或 JSON。
失败、重连、过期输入、错误身份、不该重复的请求和错误抑制均在相关边界
验证。按[开发纪律](../contracts/development.md#verify-promises-and-effects)
选择证据；单元、构建、确定性浏览器测试、真实账号和人工验收分别记录。
