# 浏览器助手的工程候选方案

本方案先探索了配置、接口和交互的实现可能性，尚未证明其复杂度符合实际使用。产品方向讨论以[产品承诺与心智模型](../product/browser-assistant.md)为入口；下文的配方、注册表、执行器、字段和设置布局均为候选，不作为后续实现必须沿用的产品结构。样例校验与原型交互通过，仅说明相应候选的局部性质。

产品方向已通过；翻译专项建设已按用户确认移出近期范围。下文翻译接口和相关样例仅保留为未来参考，不构成当前交付要求。

ChatGPTBox 应让用户把网页内容、AI 连接、工具与结果呈现自由组合，并提供开箱即用的配置。普通功能只需要名称和提示词；需要原文高亮、多模态、工具循环或持续任务时，再添加相应接口。用户可以手写、通过表单修改，也可以让 AI 生成，三者操作同一份配置。

本次交付包含产品交互、接口语义、迁移方案，以及[配置 schema](browser-assistant-config-exploration/config.schema.json)、[十个完整样例](browser-assistant-config-exploration/examples.json)和[结果契约](browser-assistant-config-exploration/contracts.json)。这些是待实现的设计契约，当前扩展尚不能导入执行。

## 产品入口与配置过程

面向用户使用“功能”和“功能组”；本文把一份可执行的功能配置称作“配方”。“工具”专指可供 AI 或执行器调用的接口，避免与按钮混淆。

浏览器中的划词栏、右键菜单、输入框菜单、侧栏和命令入口都引用同一配方。修改一次即可同步；入口决定何时显示，不另存一份提示词。站点适配包可以增加文章、评论区、视频字幕等资源，也可以提供合适的按钮位置。

工具设置页调整为功能库，保留当前 `Tools` 入口。功能库支持从预置添加、复制修改、导入、直接编辑和“帮我配置”。组只负责收纳，同一配方可出现在多个组。批量更换连接时明确修改哪些配方，不增加按组继承的上下文或工具规则。

### 创建与修改

1. 从预置选择“链接速览”。编辑器先显示名称、提示词和“跟随默认”的连接，其他项目折叠。
2. 用户可以插入变量，也可以把资源拖入提示词。选“原文标注”输出时，编辑器补齐对应结果 schema，并展示这次改动。
3. 用户在同一编辑器切换表单、配置文本、AI 修改。表单不认识的扩展字段原样保留；不把未知配置静默删除。
4. 右侧试用区展示实际输入来源、连接、工具、结果和定位情况。先查看上下文无需调用 AI；点击“试运行”才发送请求。预览、保存和真正运行分别有明确状态。
5. 用户可以对任何结果继续说“只保留与我相关的新信息”“改为标出论证薄弱的地方”，直接生成对当前配方的修改预览。

在网页结果上提供“保存为功能”和“修改这个功能”。首次配置不要求用户先理解工具协议或工作流。熟悉配置的用户可以始终保留文本编辑与导入导出入口。

### 使用时的反馈

普通调用仍然是一键执行。结果区用紧凑说明展示“读取选文”“仅发送链接”“正文与兴趣记录”等实际来源，可展开查看连接、消耗、工具步骤和原文引用。需要登录、绑定连接或缺少能力时，在对应位置给出可操作的原因。

快捷栏按当前上下文显示已启用功能：选文、可编辑输入、文章、视频等。排序、数量、图标和是否出现由用户配置。预置的推荐入口不构成功能数量上限。

## 一份逐步展开的配置

最小配方只有三个字段，默认使用当前连接，一次生成，在面板显示结果：

```json
{
  "version": 1,
  "name": "链接速览",
  "prompt": "{{url}} TL;DR"
}
```

这个最小配置保证发送所写的提示词，不保证远端读到了网页。正式“链接速览”预置通过连接槽位要求 URL 读取能力，结果区显示实际访问说明与可用出处。用户仍可自由把 URL 当作普通文本使用，宿主不从任意提示词推断并强制增加读取动作。

单份导入时宿主分配稳定 ID；配置包中的配方必须带 ID，便于引用、更新与去重。`version` 是配置格式版本；安装版本、编辑 revision、绑定关系另存于本机。

| 可选项 | 含义 | 示例 |
| --- | --- | --- |
| `engine` | 使用的连接或待绑定槽位 | `@research` |
| `resources` | 为变量提供数据 | 文章、截图、兴趣记录、当前配置 |
| `attachments` | 将资源作为独立媒体附件发送 | `["{{image}}"]`，由资源值提供 MIME 类型与本机内容句柄 |
| `tools` | 执行器可以调用的工具 | 网页读取、检索、另一个配方、完整外部 agent |
| `runner` | 怎样执行 | 一次生成、工具循环、直接调用工具、任务委派、扩展流程执行器 |
| `inputs` | 本次运行由用户填写的参数 schema | 目标语言、文件地址、自定义任务 |
| `response` | 结果的数据结构 | 原文标注集、表格、自定义 JSON schema |
| `outputs` | 把结果用于哪些位置 | 面板、原文标注、输入框修改、配置修改预览 |
| `expose` | 出现在哪些入口 | 划词栏、网页菜单、输入框菜单、配置编辑器 |
| `requires` | 本次任务必须具备的能力 | URL 读取、工具调用、任务恢复 |

核心只规定这些装配位置和引用方式。`use` 是开放的注册接口 ID；`with` 由该接口的 schema 解释。新功能通常由提示词、接口或执行器提供，不增加核心业务动作枚举。顶层未知字段提示可能拼写错误；扩展元数据放在 `extensions` 的命名空间中。

以下配方使用普通文字模型也可以生成导读和高亮。AI 选择内容，宿主负责校验和呈现：

```json
{
  "version": 1,
  "name": "为我导读并标注",
  "engine": "@fast",
  "prompt": "根据文章和可选兴趣挑出值得关注的原文，并解释原因。\n{{article}}\n{{interests}}",
  "resources": {
    "article": { "use": "page.article", "with": { "anchors": true } },
    "interests": { "use": "@interests", "optional": true }
  },
  "response": { "schema": "box.reading-result@1" },
  "outputs": [
    { "use": "panel.markdown", "select": "/guide" },
    {
      "use": "page.annotations",
      "select": "/annotations",
      "with": { "snapshot": "{{article.snapshot}}", "mode": "preview" }
    }
  ]
}
```

`select` 使用 JSON Pointer，从同一次结果中取数据。复杂对象在表单中可视化，配置文本仍然可完整表达。不在模板中添加 JavaScript、循环、条件和任意表达式；有这些需求时选择能处理它们的执行器。

## 连接与执行能力

L1、L2、L3 用于说明执行方式，避免把厂商名写成产品能力。

| 能力层级 | 可以提供什么 | 对配方的影响 |
| --- | --- | --- |
| L1 API | 文字、多模态、结构化输出、工具调用，以及部分 API 内置的搜索或 URL 读取 | 按本次接口与模型实际能力使用；API 不等于只会文本补全 |
| L2 有边界的 agent | 在一个任务内搜索、调用工具、推进若干步骤 | 可以整个委派，也可以由扩展把 L1 与工具组成一个有限 agent |
| L3 持续工作的 agent | 任务持久化、断开后查询、重新连接并继续工作 | 需要真实任务标识与恢复语义；浏览器可重新连接它 |

同一连接可以有不同模式；API 或 MCP 是传输方式，不能据此推断层级。有聊天历史、长超时或后台标签页，也不能单独证明任务可恢复。

运行前检查“连接与模型 + runner + 工具 + 站点资源 + 当前授权与浏览器会话”能否完成本次配置。能力目录区分已知支持、已知不支持和未知，并记录声明来源、适用模式与验证时间。例如 `tools.call`、`input.image`、`web.url.read`、`task.resume` 是独立能力，不能相互推断。

配方未指定连接时沿用网站连接，再沿用全局默认；本次临时选择优先于配方指定。确定顺序为“临时选择 → 配方 → 网站 → 全局”。每个结果保存实际使用的连接，继续对话时沿用它。子配方可以独立选择连接，保留调用链。

已知不支持必需能力时不发送请求；未知时显示待确认或允许用户选择尝试。候选连接只用于建议，不静默换模型、换 API、扩大输入范围或换成另一浏览器会话。能力声明本身不授予调用权限。

## 资源读取与模板语义

`{{selection}}`、`{{content}}`、`{{url}}`、`{{title}}`、`{{language}}` 保留为内置资源的简写。现有其他模板变量通过兼容目录继续提供。显式 `resources` 同名定义可以覆盖默认来源，并在编辑器显示来源改变。

| 来源 | 明确语义 |
| --- | --- |
| URL | `{{url}}` 默认使用当前 URL；预置可显式选择去跟踪参数或仅路径。不会顺便上传正文 |
| 选文 | 没有选文时返回缺少输入，用户可改选正文版本；新配方不自动扩大范围 |
| 正文 | 本机抽取当前可访问内容；保留抽取方式、范围、缺失与截断信息 |
| 图像或截图 | 作为带 MIME 类型的独立附件传给支持它的连接，不把图片地址当作图片已被读取 |
| 字幕、评论、代码差异 | 由匹配的站点资源接口提供，注明分页、加载范围、时间戳或行号 |
| 画像与知识库 | 用户选择的资源接口，可来自本机记录、已有阅读库、MCP 或其他连接 |

URL 的 `raw`、`drop-tracking`、`path-only` 是 `page.url` 的选项。`drop-tracking` 只删除清单中的跟踪参数，保留 `id`、`v`、`q` 和有意义的片段；`path-only` 明确移除查询和片段，预览结果链接。不能用“清理 URL”隐含抹掉资源身份，也不默认采用网页自己声明的 canonical URL。

声明资源不会自动把它发送给 AI。模板、附件、工具配置或输出配置实际引用它时才读取；同次运行缓存同一资源快照。媒体通过 `attachments` 显式绑定，不能由模型支持多模态这一事实自动触发。资源返回 MIME 类型与内容句柄，连接适配层负责实际上传或传输；元数据里的普通 URL 不当作已经提供的图像。

点击功能时创建不可变的 `RunContext`，固定 tab、frame、文档导航代次、选区副本、可编辑目标、浏览器会话与连接选择，随后生成实际引用的依赖计划。运行前解析模板、附件及输出配置需要的输入资源，不等生成完成才首次读取标注所依据的文章。用户切换标签页或选区消失不会改变本次输入；截图接口不能定位原标签页时报告无法捕获。工具后续读取新页面会产生新的资源与快照记录。

资源别名指向其数据值；来源、时间、浏览器会话和范围信息由运行记录保存。`optional` 只允许资源未绑定或不存在时返回明确的 `{"$unavailable":"not_bound"}` 等缺失值，不把拒绝访问、传输失败或错误读取伪装为空内容。

模板只允许变量与属性路径。`prompt` 中按资源声明的文本格式序列化；锚定正文的序列化保留 snapshot、ref 和原文。`with` 中整段占位符保留原 JSON 类型，嵌入字符串时转为文本。所有资源值解析后再次按接收接口校验；不存在的路径、依赖环和截断情况均可定位到字段。

结果 `select` 遵循 [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901)：字段不存在是错误，合法的 `null` 是一个实际值。接收接口另行声明能否接受它，不能把两者都转换成空字符串。

## 开放接口与原文位置

资源、工具、连接、执行器与输出都有注册描述：稳定 ID、版本、说明、配置 schema、输入输出 schema、适用环境和实际影响。资源负责提供输入，工具供执行器按需调用；二者可以复用同一个实现。新接口来自随扩展发布的模块、安装的站点包或工具连接。导入一份 JSON 不会自动安装或执行其提到的代码。

公共调用返回类型化产物 `Artifact`，携带 schema、媒体类型、数据与来源。模型回答先作为候选数据校验，再成为产物。输出分为呈现和效果两类：面板只消费产物，修改网页、输入或记录则生成带前置条件的效果请求，由宿主执行和记录。工具调用也必须独立鉴权；共用的是校验与效果实现，不能把返回的数据直接当作已获授权的命令。

一次运行采用以下共同过程：

```mermaid
flowchart LR
  A[任意浏览器入口] --> B[解析配方与本机绑定]
  B --> C[按需读取资源与能力检查]
  C --> D[执行器与实际连接]
  D --> E[校验结构与原文引用]
  E --> F[面板 标注 输入修改 导出]
  D <--> G[开放工具与其他配方]
```

### 页面读取

网页资源先创建快照身份，绑定标签页、文档导航代次、frame、浏览器会话和抽取范围。输出的数据形态可以是：

```json
{
  "snapshot": "snapshot-7",
  "title": "示例文章",
  "blocks": [
    { "ref": "p12", "text": "浏览器中的内容会随着页面交互而变化。" }
  ],
  "coverage": { "scope": "article", "complete": true }
}
```

`ref` 是宿主给原文的引用，不由 AI 创建。宿主保留从抽取文本到原始 DOM 的映射；不同 frame、Shadow DOM、视频时间与代码行使用相应定位器。无法映射时资源明确标为不可原位定位，仍可用于总结或面板引用。

### 标注与其他写入

标注接口接收目标、引文、理由和可选样式，不知道“重点”“争议”“与我相关”这些业务类别。例如：

```json
{
  "target": {
    "snapshot": "snapshot-7",
    "ref": "p12",
    "quote": { "exact": "浏览器中的内容会随着页面交互而变化。" }
  },
  "reason": "这会影响跨多步操作时定位结果的可靠性。"
}
```

快照与 ref 用于本次精确定位；`exact`、`prefix`、`suffix` 用于核对与恢复候选。采用这些选择器的思路来自 [W3C Web Annotation](https://www.w3.org/TR/annotation-model/)，初版内部对象不宣称完整符合 JSON-LD 标准。持久标注另存稳定页面身份、引文与创建来源，不直接复用失效的临时 ref。

页面变化后先核对目标范围。唯一匹配且上下文一致时可重新定位；有歧义则显示“未定位”及原文卡片，不猜位置。单条失败不丢弃其他有效标注；校验结果逐条保留。不同运行产生的标注可分别显示、隐藏、替换和撤销。

结构化生成、AI 工具调用和外部 agent 的结果最终经过同一标注校验与写入接口。支持工具调用的连接可在运行中使用它；只会生成文本的 L1 可按结果 schema 返回 JSON，再交给输出接口。生成了合法 JSON 不代表引文正确，仍要核对页面。

连接支持原生结构化输出时使用它；否则按约定解析候选 JSON 并校验。解析或 schema 校验失败时保留回答与错误，尚未准备好的写入输出不执行。把 JSON 当候选数据处理，与解析工具调用、执行任意代码是不同路径。

输入框修改同样绑定 target、baseRevision 与原文，支持差异预览和撤销。运行后用户已经修改输入时先重新核对，不能直接覆盖。标注、翻译、输入修改等接口的 `preview`／`apply` 由配方与用户运行策略决定，用户可以配置直接应用。

多个输出在执行前分别准备和校验，结果按输出记录成功或失败；不承诺跨网页、文件与外部服务的原子事务。每次效果带 operation ID 和回执；重复投递去重，撤销能力由具体接口声明。面板渲染内容按文本或安全 Markdown 处理。

## 执行器与持续任务

默认 `box.generate` 只执行一次生成请求；配置 `tools` 却选了不会执行工具的 runner 时给出错误，不静默忽略。表单添加工具时可以同步建议改用 `box.agent-loop`，将这个变更展示给用户。

`box.agent-loop` 在一次运行中反复接收模型的工具调用、校验参数、调用工具并反馈结果。支持原生工具调用，或用户明确选择的协议适配器；普通回答里的代码块不当作工具调用执行。轮数、用量、超时与取消来自用户可修改的运行策略，达到限制后保留进度。

`recipe.call` 把另一个配方作为工具复用。子配方独立选择输入、连接与输出，调用链共享总预算并防止无限递归。调用参数 schema 来自目标配方的 `inputs`，返回契约来自 `response`，默认是文本；授权范围不能因嵌套扩大。调用选项默认只返回产物，不运行子配方的呈现或写入输出；需要沿用输出时显式选择，并分别校验。这样多个连接与整套助手都能参与组合。

显式顺序、分支、循环可以由单独注册的流程 runner 提供；其 `with` 使用自己的 schema，步骤可引用配方和连接。核心格式无需先定义一套通用图语言。AI 自选工具和用户明确编排都能使用同一接口与运行记录。

`box.tool` 直接调用一个完整工具，文件转换等操作不必经过 AI。`box.delegate` 将任务交给外部执行器；外部 agent 也可以通过工具接口嵌入本地循环，前提是保留它的任务标识、状态和浏览器会话信息。

执行器统一接受本次输入、产物契约和宿主调用上下文。扩展开放的资源、工具和效果必须经过宿主检查，第三方 runner 也使用相同通道。外部服务内部的步骤按其真实可见程度展示；不能把服务自行报告的过程标为宿主已验证，也不能编造它没有提供的撤销或恢复能力。

每次运行保存 run ID、配方 revision、接口与连接版本、资源引用、步骤事件、结果、写入回执和外部 taskRef。运行状态至少能表示执行中、等待用户、已完成、失败、中断、取消与写入结果未知；显示给用户的控制只来自执行器真实支持的能力。

扩展自己的有限循环初期由可见的扩展页面承载，进度落盘；页面关闭后标为中断。后续恢复需要核对步骤回执与资源版本，不能通过重发整段提示词冒充恢复。外部持续任务依靠 taskRef、状态查询、事件游标和重新连接继续跟踪；历史消息本身不是恢复凭证。

任务的观察、取消和恢复执行分别声明为能力。taskRef 与事件游标只证明可以重新观察；要声明 `task.resume`，执行器必须保存可恢复的工作状态并实现恢复执行，而不只是返回旧消息。

不能依赖 service worker 常驻承载持续任务。Chrome 的 [service worker 生命周期文档](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)说明其可能因空闲或运行限制而终止。浏览器休眠后通过账本重新连接任务；上游不具备恢复语义时明确显示中断。

写动作发出后回执丢失时，先查状态或回执。无法确认则保留“结果未知”，不自动再提交。重新连接、查询进度与重新开始任务分开；自动重试规则由接口的幂等性和用户策略决定。

## 站点适配与成熟能力接入

站点包分别提供资源解析、原文定位和按钮位置；不把“这个网站只能总结”写进适配。GitHub 的差异、讨论和 README，视频站的字幕与时间点，社区的主帖与评论，可以被同一配方引用，也可以组合多个配方。

商店发行版的实现代码随扩展打包，声明式站点规则与外部工具连接可独立更新。新增代码接口通过扩展版本或明确的用户脚本宿主接入，不能因为装在 JSON 中就把远程代码当成普通配置执行。这一区别遵循 Chrome 的[远程托管代码说明](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)，不限制通过已有接口生成新的组合。

常见站点用声明式 URL 匹配、选择器、排除项、字段映射与挂载点；复杂站点允许代码实现。匹配时展示命中规则与来源。资源提供者按“用户覆盖 → 匹配的官方站点包 → 通用抽取器”选择；同级优先级与顺序明确可见，数据抽取和按钮挂载分别解析。

每个资源调用固定使用哪个提供者。正文抽取失败可按用户选择切换通用抽取，但必须显示来源与范围改变。更新采用官方基线、新版本与本地修改的三方合并；字段冲突保留本地版本并提示处理，不能覆盖用户修改。

| 能力 | 通过什么接口暴露 | 接入条件与范围 |
| --- | --- | --- |
| MarkItDown | 一个转换工具，将 URI 或显式提供的文件转换为 Markdown | 官方 [MarkItDown MCP](https://github.com/microsoft/markitdown/tree/main/packages/markitdown-mcp)需要外部运行环境；扩展连接它，返回内容不冒充有当前 DOM 锚点 |
| Browser Use | 完整任务工具或外部执行器，保留任务与会话身份 | [Browser Use](https://github.com/browser-use/browser-use)有本地与云端能力；具体接入检查实际任务接口，并明确使用当前浏览器还是独立浏览器 |
| 翻译服务 未来参考 | `translation.batch` 仅为候选示意，近期不建设专用接口 | 后续参考 Kiss Translator、Read Frog 等成熟实现。[沉浸式翻译的自定义服务](https://immersivetranslate.com/en/docs/services/custom/)是让其调用外部服务，不能据此假设可反向调用其完整渲染器 |
| 既有阅读库 | 读取、检索、标注与笔记工具 | 例如 [Readwise MCP](https://readwise.io/mcp)，复用用户已有资料，不要求先迁入一套新知识库 |

工具接收的 URI 属于服务自己的运行环境；例如文件 URI 不能默认指向浏览器用户的本机文件。绑定时说明运行位置，显式选择文件传输方式，并保留转换来源与结果类型。

网页翻译的分段、增量加载与双语呈现留作未来接入视野，优先复用成熟实现。现有翻译提示词可以继续使用通用配置，不据此启动翻译专项建设。

## 兴趣记录与配置助手

画像是可选的普通资源。用户可以手写、选取现有阅读库记录，或让 AI 在某次任务中提出修改。配方声明读取哪些字段；不因启用“导读”就默认读取完整浏览历史。

更新使用带 baseRevision、依据来源与差异的补丁，支持查看、回滚和范围限制。可以配置每次预览，也可以在指定字段与站点范围内自动更新。读取已有兴趣、提出更新、应用更新是三个可独立调用的接口。

“帮我配置”本身也是预置配方，可改连接与提示词。宿主向它提供当前配置与 revision、实际可用目录、配置 schema、所需接口 schema 和相关例子。完整目录过大时使用检索；每次调用都提供所需上下文，不依赖模型保留前次讨论。

AI 返回补丁及说明。宿主核对 revision、应用到临时副本、解析依赖、做能力检查，再展示差异和试用结果。AI 不得凭文字声称某接口存在。用户在另一处改过配置时重新合并，保留未知字段；应用后保存可撤销版本。

任何外部 AI 也可以生成相同格式。导入包携带连接槽位和接口引用，本机负责绑定；分享不包含密钥、Cookie、真实 taskRef、本机文件和画像内容。缺依赖时保留为待绑定状态，不把整份配置作废。

## 校验与可理解的失败

| 层次 | 自动检查 | 不能由这一层证明什么 |
| --- | --- | --- |
| 结构 | JSON schema、字段类型、输入表单、JSON Pointer | 连接可用、网页可定位 |
| 装配 | 真实接口与槽位、变量路径、I/O 类型、资源依赖环、调用循环 | 远端服务具备所宣称的能力 |
| 试读与能力 | 本次资源、实际输入范围、连接模式、浏览器身份、必需能力 | AI 将生成正确结论 |
| 结果与效果 | 结果 schema、逐字引文、快照、输入版本、效果回执 | “值得关注”是否符合用户判断 |

错误应指出字段和修复办法，例如：“`resources.article` 没有可定位原文；可以改用面板引用或切换抽取器”“翻译连接未绑定”“文章中的 2 条标注无法唯一定位”。保留原始结果供修改，不把失败输出当作成功执行。

页面内容、检索结果与工具返回值作为资料传递，不能自行改变配方、授权范围或宿主指令。安装接口的能力说明与实际权限分开校验。运行记录只保存恢复与解释所需的信息，正文保留期限可配置，连接凭据不进入日志。

## 预配置与交付顺序

预配置用于展示组合方法，允许复制、改写、删除与分享。功能库首屏推荐少量常用项，按上下文呈现；更多能力在库中添加。

| 场景 | 首批提供的可编辑变体 |
| --- | --- |
| 阅读 | URL 速览、当前正文总结、选文总结、导读与理由、论证检查、查证后导读 |
| 翻译 未来参考 | 既有提示词沿用通用机制；新增翻译能力与专用呈现暂缓 |
| 写作 | 输入改写、按语气草拟回复、对照差异、选文润色 |
| 多模态 | 区域截图解释、OCR 文本提取、图片提问；只显示当前连接支持的方式 |
| 结构化内容 | 提取表格、文章与评论对照、字幕导读、代码差异讲解、文件转 Markdown |
| 个人使用 | 按兴趣标注、结合阅读库解答、提出兴趣记录更新 |
| 配置与代理 | 帮我配置、复用另一个配方、交给浏览器 agent、接入外部流程 |

### 第一批建立完整的日常使用链路

提供开放配置、功能库、逐功能连接、按需资源、统一入口与结果接口。完成 URL／正文／选文三种路径、原文标注、输入修改，以及 schema 校验和试读。把配置助手作为相同接口的一个使用者一起交付。

此时即可验收“日常阅读”组内使用三个不同连接，和“普通文字 API 生成原文标注”。这批的接口已经允许注册新的资源、工具和输出；功能数量由配置增长。

### 第二批接通工具与外部能力

实现工具循环、`recipe.call`、MCP 工具映射、直接工具调用和外部任务委派；接入文件转换、浏览器 agent、阅读库，扩展站点包。接口目录同时用于 UI 和 AI 配置助手。显式流程 runner 可以在这一批作为独立模块接入。

### 第三批补全持续任务体验

完善任务账本、外部任务重新连接、事件恢复和可确认的步骤恢复。持续任务的承载条件和能力保持可见；后端已具备这些能力时可以较早接入，不必等待全部本地循环恢复完工。

## 现有代码的接入与迁移

截至本次检查，实际设置页由 `src/options/SettingsCenter.jsx` 组织，使用 `Tools`、`Sites`、`Engines` 等入口。按实际代码迁移，不按旧版设置说明推断已有 agent 运行时。

| 现有位置 | 已有能力 | 设计中的调整 |
| --- | --- | --- |
| `src/config/storage.mjs` | 六项默认启用、用户划词工具、网站连接 | 增加配方与本机绑定存储；旧字段保留迁移依据 |
| `src/content-script/selection-tools/index.mjs` 与 `menu-tools/index.mjs` | 内置提示词与菜单动作 | AI 功能转为预置配方；打开窗口等扩展操作仍由普通 UI 处理 |
| `src/utils/prompt-template-context.mjs` | 按需变量读取与上下文预算 | 包装为资源解析，补充来源、结构化值、附件和缺失语义 |
| `src/utils/get-core-content-text.mjs` | 选择器、Readability 与通用抽取 | 保留抽取能力；新增快照到原始 DOM 的映射，不能用纯文本抽取冒充定位能力 |
| `src/components/FloatingToolbar/index.jsx` | 点击后生成提示词，展示聊天卡 | 改为提交配方调用，按结果接口显示内容 |
| `src/content-script/index.jsx` 与 `src/utils/site-engine.mjs` | 创建 session 前已按网站／全局选择引擎 | 点击具体功能后才确定配方连接；继续会话沿用原连接 |
| `src/background/providers/adapter-contract.mjs` | match、run 与可选 supportsTools | 先以新适配层包装，逐步补充模式、输入输出与任务能力，布尔值不足以代表全部能力 |
| `src/content-script/site-adapters/` | 搜索输入与挂载位置、部分专用提取逻辑 | 拆成可分别注册的资源、定位和位置接口，原实现可逐个包装 |
| `src/popup/sections/SelectionTools.jsx` 与 `ToolsTab.jsx` | 提示词编辑、图标和启用开关 | 作为功能库与编辑器的迁移入口；UI 与 AI 共享 schema 和目录 |

新增逻辑集中在浏览器助手模块，先通过适配层调用现有 provider，不改写 API Bridge、MCP server 或厂商客户端。第一批默认聊天仍可沿用 `ConversationCard`；标注与输入修改各自处理结果。

迁移一次性把旧内置工具生成预置配方，把 `customSelectionTools` 转为用户配方，保留名称、提示词、图标、启用状态与顺序。旧 `usePageContext` 的“没有选文就用正文”通过显式兼容资源保留，并在编辑器说明；不改变旧工具的数据范围。旧模板别名继续有效。

未指定逐功能连接的旧工具继续按网站与全局设置运行。迁移保留原始导出快照和来源 ID，幂等执行；同名工具不合并。官方预置更新只更新未修改的副本；修改过的配方使用三方比较。

## 验收场景

1. 只写最小三个字段即可运行 URL 提示词；输入预览中没有正文。选择仅路径策略后能看见实际发出的 URL。
2. 同组的 URL 速览、选文总结、原文导读绑定三个不同连接；点击各自功能后使用各自连接。
3. 普通文字 API 返回结构化导读与标注。修改“值得关注”为“论证缺口”只改提示词，不改接口实现。
4. 兴趣记录未绑定时仍可通用导读；绑定后只读取指定资源。更新可预览、按策略应用并撤销。
5. 页面重新渲染、重复引文、iframe 与输入框被用户改动时，不把结果写到错误位置。
6. AI 添加未知工具、错误变量或错误输出路径时，编辑器定位错误；修复后表单与文本往返不丢字段。
7. 一个配方通过 `recipe.call` 使用另一连接，并调用完整文件转换工具；记录能还原调用链与实际数据范围。
8. 连接无图像、工具或 URL 读取能力时，给出对应原因；不自动上传更多页面内容或换连接。
9. 外部浏览器 agent 的当前浏览器与云浏览器绑定清晰。浏览器关闭重开后，用原 taskRef 继续查询真实持续任务。
10. 写入已发出但回执丢失时保留不确定状态；取消、恢复、重新执行分别符合实际后端语义。
11. 导入分享包只需要绑定连接槽位；不携带密钥或个人资料。官方更新保留用户修改。

配置样例可在仓库根目录使用 Node 20 运行 `node docs/history/browser-assistant-config-exploration/validate.mjs` 检查。该脚本校验配置结构、已声明接口、槽位、结果 schema、变量根和输出字段引用；接口目录是设计夹具。真实绑定、模板路径的数据值、能力组合、网页定位和实际运行属于实现阶段验收。

## 相关产品对设计的启发

[Monica PowerUP](https://monica.im/help/Features/PowerUP/Customize_PowerUP)的站点、内容范围、提示词和连接配置说明一键功能可以保留丰富装配；[HARPA ChatML](https://harpa.ai/chatml/overview)展示了可编辑自动化与高级编排的价值；[Obsidian Web Clipper](https://obsidian.md/help/web-clipper/templates)的可分享模板和[简悦配置库](https://github.com/Kenshin/simpread-configs)说明预配置本身值得持续维护。[Readwise Ghostreader](https://docs.readwise.io/reader/guides/ghostreader/global)的可编辑技能、资料引用与标注能力，也支持把日常阅读交互做完整。

本设计把这些成熟经验用于 ChatGPTBox 的配置、网页资源和结果接口。与实际本机代码的衔接由迁移层完成，不要求用户理解供应商适配细节。
